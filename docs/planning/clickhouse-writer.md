# CYS-STO-007：批量 native 写入与失败重放

本批实现 FlowRecord JSONL -> 持久化批次队列 -> 官方 clickhouse-client -> native TCP。
Go 标准库负责队列、背压和 CLI，不在仓库内重写 native 协议或增加第三方驱动。

- 批次由条数、字节上限和刷新间隔限制；单条记录另有大小上限。
- Enqueue 成功只表示批次文件与目录完成 fsync；交付成功在客户端收到同步 INSERT 成功后。
- 待发送批次含随机 ID、条数和 SHA256；临时文件写完同步后原子改名，确认发送后删文件并同步目录。
- 队列包含正在发送的批次，按文件真实字节限制；满时 Enqueue 等待容量或调用方取消，不静默丢弃。
- 同一目录只允许一个进程；目录绑定目标地址/库/表，防止重放到另一个目标。损坏与未完成文件明确报错。
- 失败按固定间隔重试，达到上限退出非零并保留队列；重启先重放已有批次。
- 每次重试复用持久化的 insert_deduplication_token。非复制 MergeTree 必须另启用
  non_replicated_deduplication_window；窗口有限，不宣称无限期 exactly-once。
- 输入未形成并持久化的内存尾批，不属于已接收记录；进程异常退出后，上游须按自己的确认/检查点重送。
- `--resume-file` 为不可变普通文件保存源路径/长度/SHA256/字节偏移/累计行数；批次源范围先持久化，
  检查点后更新，重启先从完整批次恢复连续高水位，再从源文件续读，完成文件重跑零发送。
- 源范围和检查点有独立校验；源变更拒绝沿用。文件模式保留并计数未提交临时文件，从源重读；
  普通队列仍要求手工检查遗留临时文件。
- IPFIX 采集器 `--durable-output` 同步临时文件后不覆盖地原子发布并打印持久化文件回执。

验收：Go 单测/竞态检查覆盖文件损坏、目标绑定、容量等待、取消和失败保留；Compose 验证
两档逐字段读回、服务不可用后重放、ACK 丢失重试去重、服务恢复后背压解除。
本批不接实时 UDP 采集器、不作物理服务器高吞吐承诺；每批启动一次官方客户端的开销需如实测量。
文件交接另以 `check-clickhouse-resume.py` 验证采集发布、部分断点、源变更拒绝与 SIGKILL 恢复。
