## 关口做了什么（`check-training-project.sh`）

设计原则：**缺工具/缓存为空是失败，不是"跳过即通过"**。默认 `--offline`；首次搭建用 `uv sync --project ml/training --locked`，需要下载时显式 `--online`。

- **元数据自证（7 项注入，全部在临时树里做，不碰工作区）**：项目版本 ≠ 根 `VERSION`、Python 引脚改 `3.12.0`、锁里 setuptools 版本漂移、后端写成 `setuptools>=`（非精确）、归档哈希前缀改 `sha512:`、入口点改到不存在的模块、以及用真实 `uv lock --check` 验证**锁文件过期必须非零退出且报 `lockfile`**。
- **白名单不藏源码（正反两向）**：临时 git 仓库里 `.venv/`、`build/`、`*.egg-info/` 的 `.py` 文件被放行（基线通过）；随后写入 `ml/training/features/real-source.py` 并加 `*.py` 忽略规则 ⇒ 必须判红**并点名该文件**。只做前者会漏掉"白名单过宽"这一类。
- **提交钩子依赖边界**：首次提交被密钥扫描拦下，28 处通用赋值命中均位于本地 setuptools 的 9 个依赖文件，文件摘要与安装包 RECORD 一致。现仅排除 `ml/training/.venv/` 的依赖命中；向真实训练源码注入同类赋值仍判红，且不回显匹配值。该反向验证已挂入本关口，未绕过 pre-commit。
- **整包隔离安装（smoke）**：先断言门禁运行在钉扎解释器上 → `uv lock --check` → `uv build`（**从 sdist 构建**，这样 MANIFEST 漏文件藏不住）→ 校验 wheel 内含 `dataset.py` 与 `schema_gen.py` → 新建独立 venv、`--no-deps` 只装该 wheel → 在仓库外目录用 `python -I` 导入，**断言模块文件路径在 venv 前缀内**（防"装上了但 import 的是仓库源码"）→ 校验 `importlib.metadata` 版本 = 根 `VERSION`、**运行时依赖为空** → 用安装后的 `cythsec-features` 在仓库外 `build` + `validate` 一份与 MLT-006 同源夹具的产物，并对手算向量（2 包/6 字节/熵 1.0 bit）断言。
