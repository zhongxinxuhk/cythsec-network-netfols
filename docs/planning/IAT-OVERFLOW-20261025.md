## 范围与分支

## 已复现的缺陷

1. `push(u64::MAX)` 两次：单个平方可容纳于 u128，两个平方之和不能；debug 崩溃，release 会回绕。
2. 两个各含一次最大 IAT 的摘要合并：同样在平方和加法处溢出。
3. 向空摘要合并包含 `[10,20,30,40]` 的源（只保留最近两个）：源摘要已经整体并入后，又对保留窗口调用 `push`，导致计数从应有的 4 变成 6，并污染均值与平方和。

先加回归测试，未修复时实跑：前两条 `cargo test --offline --lib iat_square_sum` 退出 **101**；第三条 `cargo test --offline --lib iat_merge_into_empty` 退出 **101**。失败日志见 `/tmp/cythsec-iat-red-square.log`、`/tmp/cythsec-iat-red-merge.log`。

## 修复与边界

- 平方和使用低 128 位 + 高 64 位，逐次加入与合并都显式保存进位；只有渲染标准差时才转 f64。
- 位宽依据：样本计数不超过 u64::MAX 时，平方和上界为 `(2^64-1)^3 < 2^192`，因此固定 192 位足够，不需要大整数依赖或逐样本分配。
- `retain()` 只维护保留窗口；空摘要合并采用它复制样本，全历史摘要只计入一次。
- 新增四项 Rust 回归：逐次加入进位、合并进位、空摘要接纳后继续加入、通过 64 次分块合并覆盖完整 u64 计数边界。最后一项按手算恒等式校验高低位：`(2^64-1)^3 = 2^192 - 3*2^128 + 3*2^64 - 1`。
- 没有选择“让平方和饱和”：对两次最大 IAT，一阶矩按既有规则饱和时，完整平方和对应离散度为 `sqrt(3)/2 * M`，平方和也饱和会变成约 `M/2`，低估约 42.3%（M=u64::MAX，手算）。
- **兼容限制仍在**：一阶矩 `sum_us` 饱和后，均值及基于它计算的离散度并非数学上的精确全样本均值/总体标准差。本批修复二阶矩溢出，未悄悄改变这条 v1 行为。超过 u64 可表示样本计数的聚合也不在支持范围内。

## 同机成本测量

产物：`measurements/iat-overflow-bench.json`，保存原始七轮数值、编译器/平台、基线提交与完整微基准源码。

方法：相同主机、相同 `rustc --edition 2021 -O`，修复前后可执行文件交替执行，每档 **7 轮、每轮 10,000,000 次** `IatRing::push`，容量 64，输入为 1..97 循环。

- 修复前中位：**1.4803584 ns/push**。
- 修复后中位：**1.5124583 ns/push**（约 **+2.17%**）。存在热身与调度波动，不据此宣称吞吐提升。
- 本机 `size_of::<IatRing>()`：**96 → 96 B**；高位字段落在现有布局余量中。这是该编译器/架构下的实测，不是跨平台 ABI 承诺。
- 逐次更新仍固定宽度 O(1)，只修改既有缓冲与摘要字段；空摘要合并仅遍历源的保留窗口，不回扫全历史。
- 该数字只描述局部微基准，不代表整条流水线、10G 线速或真实采集性能。基准源码与两个本地二进制保留在 `build/iat-overflow/`。
