# CYS-STO-007：ClickHouse 发布目录消费增量

基线 `f330c21`，任务分支 `codex/clickhouse-inbox-consumer`。沿用当前工作树，
CLion 原始检出上的 `feat/protocol-b020-smtp` 工作不在本批范围。

## 实现范围

单文件断点链路之后，补齐多个已完成采集文件的常驻交接：

1. `cythsec-ch-write --input-dir` 扫描已原子发布的非隐藏 `.jsonl` 普通文件，支持 `--scan-once`。
2. 文件名经 SHA256 映射到私有队列子目录，复用已有源摘要、字节偏移、批次 ID 与重试语义。
   同内容不同文件名保留独立记录；完成源重启不重新封批。
3. 全程根目录进程锁，输入目录和目标绑定带校验和；禁止嵌套输入/状态目录或改投目标。
   既有状态先恢复，之后才接收新文件；源缺失/变化、未知状态、超限及写入失败明确报错并保留现场。
4. 一次仅处理一个队列，批次容量为全局已提交在途批次上限；扫描条目数和保留的每文件状态数量另设上限。
   对 `.jsonl` 符号链接、目录、FIFO 拒绝消费；打开时使用 no-follow/non-blocking 并核对 inode。
   目录独立性还按文件系统身份校验，大小写别名不能绕过；运行统计以隔离快照返回。
5. 单个源只有 EOF 和全部持久化批次交付均确认后才输出完成回执。取消/失败不算完成，保留活动源统计。
6. 新真实故障检查接入 CI 的 ClickHouse 阶段；新 Python 检查纳入格式/静态质量清单。

原 stdin、单文件与重放模式保持兼容。此增量不是原生长连接优化、实时 UDP 确认、ClickHouse 查询 API
或自动保留策略；`CYS-STO-007` 继续保持进行中。

## 约束与后续

- 发布源须不可变且文件名唯一；不追踪追加或轮转。不自动删除任何源文件或检查点。
- 完成源在同一进程内按 inode/size/mtime 缓存；重启重新校验完整 SHA256，不是实时篡改监控。
- 目标不可达按现有配置进行有限重试，耗尽后退出并保留状态，交由运行环境重启；不静默跳过坏文件。
- ACK 丢失后的去重仍受目标表有限去重窗口约束，不宣称无限 exactly-once。
- 下一步应按实际采集规模测量目录数量、状态保留与持续写入开销，再决定长连接和保留策略；
  不以本次 148 条故障验收代替吞吐/长期稳定性结果。
