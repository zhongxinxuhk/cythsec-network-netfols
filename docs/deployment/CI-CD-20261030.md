# Cloud navigation and unified delivery integration

This branch integrates the current GitHub main (FlowRecord v2, Python contract/quality and native Rust storage)
with the recent ClickHouse durable JSON writer, file checkpoints and complete Pro console. It does not reset
main to the older worktree baseline. The JSONEachRow compatibility table is versioned separately as
flow_records_v2; the original v1 table remains available for historical files.

The restored navigation reuses the prior cloud-style implementation: module rail, searchable context menu,
animated collapse, global product drawer, favorites, recent visits, route-close and reduced-motion support.
It derives destinations from the current complete route tree, preserves the standard pages, applies the
existing frontend access flags and migrates legacy network favorite paths to their current redirects.

CI has one push/PR/merge-queue entry, reusable language/security/lint workflows, explicit needs order,
a complete success-only required gate, real browser/network/ClickHouse failure checks, SHA-pinned actions,
read-only default permissions, finite timeouts, evidence retention and exact-revision package checksums.
Tag delivery reuses the same entire CI before creating a draft Release; production deployment has no target.
See .github/workflows/README.md for the DAG and local reproduction.

Dependency integration keeps the full React 19 Pro template. Registered npm findings were addressed through
supported upstream updates and the existing project decoder/router/browser-polyfill adapters. Two unpatched
upstream prototype issues use distinct private, MIT-preserving source patches with attack-input regressions:
Mock.js Util.extend and deepmerge null-prototype destinations. The vendored sources are not represented as
new upstream releases. The full lock audit and actual browser/build behavior are both checked.

The fallback secret scanner distinguishes TS types, bindings, theme objects, JSON Schema and i18n message IDs
from stored literal assignments. Runtime/OIDC exemptions remain limited to exact workflow values, and new
negative tests cover uppercase/quoted literals without exposing matched text. Gitleaks remains independent.

Local macOS cannot verify Linux-specific privileged capture. Those checks run on an isolated hosted Linux
veth and remain mandatory. Registered tshark field exceptions remain explicitly unverified, not passes.

Latest-main integration retains the secure routerd/telemetryd access boundary and all real service pages,
including persistent network inspection, analytics, metric dictionary and ingest queue. The `/operations`
product groups those pages; historical network URLs redirect to the current network product. Development
design workspaces retain all five explicit routes and are excluded from production builds.

The Linux default full-suite workflow is a mandatory CI prerequisite and package prerequisite. Browser
installation is included in its shared environment. Business component/API tests use the original DOM
adapter, while the complete Pro template and navigation use actual Chromium. Both are required by npm test.
Business ESLint controls remain mandatory alongside the template's Biome gate. TypeScript is pinned to
6.0.3 with typescript-eslint 8.72.1, within its declared >=4.8.4 <6.1.0 compatibility range; the incompatible
TypeScript 7 / legacy parser combination is no longer installed at the project root.

Development and built-output preview use one browser URL on loopback port 15173, reject fallback ports
and probe for occupied ports before Umi clears its generated directory. Utoopack's compiler asset server
uses its explicit loopback-only PORT+1 internally; it is not another console entry. Existing environment
proxy variables remain supported. Stop dev before running a Umi production build or setup, because those
commands regenerate shared framework/cache files. A pre-integration local compiler cache was regenerated
after the dependency change; source files were preserved.
