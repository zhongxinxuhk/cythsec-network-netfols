### 测试捕获的真实缺陷（已修复）

`src/utils/format.ts` 的 `fmtBytes()` 对 `n < 1024` 走了通用小数分支，`fmtBytes(1)` 输出 `1.00 B`。
字节是离散计数，小数位无有效信息。已修：`i === 0` 时固定取整。并补边界用例锁定：
`0`/负数→`0 B`、`1023`→`1023 B`、`1024`→`1.00 KB`、`1024**5`→`1024 TB`（超 TB 不再进位）。

> 这个缺陷正在于「先写测试」的价值：读代码时不会觉得有问题，写了边界断言才暴露。

### 关键设计决策（编码时定型）

- **部署模式把能力可用性从文档约定提升为代码约束**：`SubActionAvailable(原语, 模式)` 是唯一判定入口。
  旁路（SPAN/TAP）物理上不在报文路径，`drop_stream`/`drop_current_packet`/`throttle_*` 返回 false。
  不做成硬约束就一定会出现「规则命中但流量照走」的静默失效。
- **诊断严重度按「是否启用」分级**：启用规则用了当前模式不可用的原语 → **阻塞错误、拒绝装载**；
  停用规则 → **提示警告、允许装载**。前者会让设备静默失去防护，必须拦。
- **`deploy_mode` 默认 `bypass`**：这是唯一「不会让人误以为已生效」的默认值。
- **白名单先于拒绝**（与论文 §4.1.2 相反）：安全设备最贵的故障是误封。
- **装载失败即致命**：规则表是安全策略，静默以空表启动＝全部阻断规则失效。
- `Registry.Install` 保持「全量成功或全量不生效」原子性，拒绝时保留旧快照。

### 修复的三处真实缺陷（本批自己引入、自己发现）

1. **求值轨迹退化为空信息行**：初版只收集**命中的**对象描述，未命中时输出
   `条件 X:  → 不成立`，恰好抹掉排查「规则为什么没生效」所需的唯一线索。
   改为未命中时列出期望对象集（上限 3 条 + 总数提示，防单条规则撑爆 `TraceLimit`）。
2. **「求值出错」与「值不匹配」混为一谈**：处置动作完全不同（改采集 vs 改规则），
   现分别输出 `求值出错: …` 与 `未匹配任何对象（期望: …）`。
3. **`Diagnostic` 缺 JSON tag**：Go 按字段原名输出（`Severity` / `RuleUUID`），
   与响应其余 snake_case 混排；前端取 `severity` 得到 `undefined`——**不报错、不崩、一片空白**。
   已补齐 tag（`Decision` / `Version` / `Snapshot` / `CompiledTable` / `RuleEntry` 一并补），
   并加契约测试 `TestDiagnosticsUseSnakeCaseKeys` 锁死。

### 环境经验（可复用）

- **后台进程会被 Bash 工具调用结束一起收走**：`(cmd &)` 启动的服务下一轮就 `Connection refused`，
  必须用后台运行模式启动常驻实例。
- **本机 `http_proxy` 会劫持对 127.0.0.1 的 curl**（返回 `502 upstream connect failed`）：
  冒烟前 `export no_proxy='*' NO_PROXY='*'`。把命令塞进 shell 变量再 `$C` 在 zsh 下不可靠。
- **生成物格式化**：生成 Go/Rust 后需显式调 `gofmt` / `rustfmt --edition 2021`（edition 与项目
  不一致会产出与 `cargo fmt` 不同的结果）。
