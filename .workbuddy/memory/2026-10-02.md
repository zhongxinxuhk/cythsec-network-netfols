## 2026-10-02 DPI 深度包检测落地（CYS-TRF-019/020/021/023）

- 需求动因：用户指出「pcap 流量一大就不行」。实测证据：`pcap_file.cpp` open 时把整个文件读进 `std::vector<PacketBuffer>`（非流式、无界内存、不报丢包），省网 100G 走不通
- 新增 `datasets/dpi/` 向量体系：确定性生成器（期望值由**构造参数**推出，非解析产出）+ 21 payloads + 3 pcap + expected.json
- 三方互证：生成器 → Rust 实现 → tshark 4.6.7 独立实现（`scripts/verify/check-dpi-vectors.sh`，22 项一致，挂 `test-all.sh --dpi`）
- Rust `src/dpi/`：`mod.rs` 三级递进框架 / `tls.rs`(ClientHello+JA3) / `dns.rs` / `http.rs` / `attributes.rs` / `md5.rs`（自实现，零第三方依赖）
- 裁决语义刻意用四态枚举（`Identified / NeedMore / Malformed / Unknown`）而非 `Result`：把"不是我的协议"和"我的协议解析坏了"混成 `Err`，下游无法区分该等分片还是该丢弃
- 踩坑记录（均靠测试暴露）：MD5 的 B 初值是 `0xEFCDAB89` 不是 `0xEFCD89AB`；MD5 摘要逐 u32 输出要按小端字节；第 3 轮 G 表是 `5,8,11,14,1,4,…`；TLS 握手长度是 **3 字节从偏移 6 起**；`Cursor` 起始偏移 9；SNI 与 supported_groups 扩展体的**长度头**不能当列表元素；`supported_versions` 长度头是 1 字节（不是 2）
- 生成器自身缺陷：`tls-bad-inner-len` 偏移漏算 4 字节握手头，改坏的是 random 不是 cipher_suites → 畸形样本必须真的畸形
- 已知例外不冒充通过：ECH 向量无法用 tshark 核验，显式标 `tshark.verified=false` + 原因，并用测试守门防止被改回 true
- 闭合缺口：`attributes.rs` 首次真正产出 `ATTR_TLS_SNI/JA3/DNS_QNAME/APP_ID`（此前字典与示例规则里有、无任何生产者）
- 反向注入验证两轮：改坏期望值 → 脚本与 Rust 测试双双报错；去掉 GREASE 过滤 → tls-grease 失败；均恢复现场并 `cmp` 字节比对
- 修复 lint 复发：上一批新增 C++ 文件未跑 clang-format → 全仓 50 个文件 `clang-format -i`，CTest 6/6 仍通过

## 约定（本项目）

- C++ 新增文件必须跑 `clang-format -i`（工具在 `/Library/Developer/CommandLineTools/usr/bin/clang-format`，不在 PATH）
- shell 中变量引用一律 `${VAR}`（macOS bash 3.2 会把紧跟的多字节字符并入变量名）
- 注释里声称「有脚本会拦下」的，该脚本必须真实存在并挂在门禁上
